1. Bisection, Regula-Falsi, Secant & Newton-Raphson

⏱ 90 min🔗 Prereq: None

🎯 Learning Objectives

By the end of this module, you should be able to:

  • Distinguish between different types of errors and understand how they propagate in calculations
  • Apply bisection, regula-falsi, secant, and Newton-Raphson methods to find roots of equations
  • Analyze the convergence rate and efficiency of each method
  • Identify when each method is most appropriate based on the problem characteristics
  • Recognize common pitfalls and failure modes of each method

📝 Theory Notes

Big idea: computers cannot solve f(x) = 0 directly — every method here just narrows a bracket or slides downhill using repeated guesses. The differences are speed vs safety.
  • Error vocabulary: round-off error (finite digits), truncation error (cutting an infinite process), absolute error $E_a=|x_{true}-x_{approx}|$, relative error $E_r=E_a/|x_{true}|$. Errors propagate: for $z=x+y$ errors add; for products/quotients relative errors add.
  • Bisection: needs a sign change f(a)f(b) < 0; halve the interval each step, keep the half that still changes sign. Always converges, linearly slow: error halves per step.
  • Regula-falsi (false position): same bracketing safety but joins (a,f(a))-(b,f(b)) with a straight line and uses its root as the next point — usually faster than bisection.
  • Secant: same line-idea but without needing a sign bracket — uses two latest points. Superlinear (order ≈ 1.62), but can wander off.
  • Newton-Raphson: slide down the tangent at the current guess:
$x_{i+1}=x_i-\\dfrac{f(x_i)}{f'(x_i)}$ — quadratic convergence: correct digits roughly double each step. Fails when f' ≈ 0 (flat), poor initial guess, or multiple roots. General iterative form: $x=g(x)$ fixed-point iteration converges iff $|g'(x)|<1$ near the root.

⚠️ Common Mistakes to Avoid

  • Forgetting to check sign change: Bisection and regula-falsi require f(a)f(b) < 0. Always verify this first!
  • Using Newton-Raphson near flat spots: If f'(x) is close to zero, the method can diverge wildly. Check the derivative magnitude.
  • Confusing secant and regula-falsi: Both use lines, but secant doesn't require bracketing while regula-falsi does.
  • Assuming all methods converge: Only bisection is guaranteed to converge with a proper bracket. Others can fail.
  • Stopping too early: Don't stop based on |x_n - x_{n-1}| alone — check |f(x_n)| is small enough.

💡 Tips & Tricks

  • Choose your method wisely:
    • Need guaranteed convergence? Use bisection.
    • Have derivative easily available? Newton-Raphson is fastest.
    • No derivative but have two points? Secant method.
    • Want bracketing but faster than bisection? Regula-falsi.
  • Hybrid approach: Use bisection to get close, then switch to Newton-Raphson for rapid convergence.
  • Engineering application: These methods are used to solve for unknown dimensions in design problems (e.g., find diameter of pipe for given flow rate).
  • Initial guess matters: For Newton-Raphson, sketch the function first or use physical intuition to pick a good starting point.

📖 Exam Definitions — quote these in your answers

  • Truncation error: The error caused by replacing an infinite mathematical process with a finite number of steps (e.g. stopping a Taylor series early).
  • Round-off error: The error introduced because numbers are stored with a finite number of significant digits.
  • Order of convergence: How fast successive errors shrink: if e(k+1) ≈ C·e(k)^p, p is the order (bisection p = 1, secant p ≈ 1.618, Newton-Raphson p = 2).
  • Bisection method: A bracketing root-finding method which repeatedly halves an interval containing a sign change; guaranteed to converge.
  • Newton-Raphson method: An open iterative method that follows the tangent line at the current estimate to find the next, converging quadratically near a simple root.

📘 Worked Example

Solve x³ − 2x − 5 = 0 by Newton-Raphson from x₀ = 2: f(x) = x³−2x−5, f'(x)=3x²−2 $x_1 = 2 - \\dfrac{8-4-5}{12-2} = 2.1$ $x_2 = 2.1 - \\dfrac{9.261-4.2-5}{13.23-2} = 2.0946$ $x_3 = 2.0946 - \\dfrac{0.0055}{11.16} \\approx \\mathbf{2.09455}$ ✓ (digits doubling as promised)

Teacher's note: Notice how the error decreases dramatically: from ~0.1 to ~0.005 to ~0.00005 — that's the power of quadratic convergence!

  2. Solving tan(x) = x where you know there's a root near 4.5
  3. Solving an equation where you can only compute the function value, not the derivative

2. Gaussian Elimination, LU Decomposition & Iterative Methods

⏱ 75 min🔗 Prereq: None

🎯 Learning Objectives

By the end of this module, you should be able to:

  • Solve systems of linear equations using direct methods (Gaussian elimination, LU decomposition)
  • Understand when to use iterative methods vs direct methods
  • Analyze the computational cost and stability of different approaches
  • Apply pivoting strategies to minimize numerical errors
  • Recognize when a system is ill-conditioned and what that means for your solution

📝 Theory Notes

Big idea: two philosophies — eliminate variables directly (exact up to round-off, finite steps) or iterate from a guess (cheap per step for huge sparse systems, must converge).
  • Gaussian elimination: forward elimination to upper-triangular form using row operations (pivot = divide by diagonal), then back-substitution. Cost ≈ n³/3 multiplications.
  • Gauss-Jordan: keep eliminating above AND below pivots → identity matrix; right side becomes the answer. No back-substitution needed, ~50 % more work.
  • LU (Crout/Doolittle): factor A = LU once, then solve LUX = b via two cheap triangular solves — perfect when many b's share one A. Partial pivoting (swap rows for biggest pivot) controls round-off.
Jacobi update: $$x_i^{(k+1)}=\\dfrac{1}{a_{ii}}\\Big[b_i-\\sum_{j\\ne i}a_{ij}x_j^{(k)}\\Big]$$ (all old values) Gauss-Seidel: same formula but use NEWEST available values → converges ~2× faster. Convergence guaranteed if A is diagonally dominant: $|a_{ii}|>\\sum_{j\\ne i}|a_{ij}|$.

⚠️ Common Mistakes to Avoid

  • Forgetting to pivot: Not using partial pivoting can lead to large round-off errors, especially with small pivot elements.
  • Confusing LU with Gaussian elimination: LU does the factorization ONCE, then solves for many right-hand sides efficiently.
  • Assuming all systems work with iterative methods: Jacobi and Gauss-Seidel only converge reliably for diagonally dominant or symmetric positive definite matrices.
  • Not checking for singular systems: If you get a zero pivot (after pivoting), the system may be singular or inconsistent.
  • Misapplying back-substitution: Remember to solve from bottom to top after forward elimination.

💡 Tips & Tricks

  • Choose your solver based on the matrix:
    • Small dense systems (< 100 equations)? Use LU with partial pivoting.
    • Need to solve for many different right-hand sides with same matrix? LU decomposition is perfect.
    • Large sparse systems (like from finite element analysis)? Consider iterative methods.
    • Symmetric positive definite matrix? Cholesky decomposition is ~2× faster than LU.
  • Engineering application: Structural analysis, circuit analysis, finite element methods all reduce to solving Ax = b.
  • Check your work: After solving Ax = b, compute the residual r = b - Ax. It should be very close to zero.
  • Condition number matters: Even if your algorithm is correct, a high condition number means small errors in A or b can cause large errors in x.

📖 Exam Definitions — quote these in your answers

  • Pivoting: Interchanging equations (rows) during elimination so the pivot element is the largest available in magnitude, minimising round-off amplification.
  • LU decomposition: Writing A = LU where L is lower- and U upper-triangular, allowing repeated solutions for different right-hand sides with only two triangular solves.
  • Gauss-Seidel method: An iterative solution scheme that immediately uses updated component values within the same sweep, converging under diagonal dominance.
  • Diagonal dominance: Property |aii| ≥ Σ|aij| (j ≠ i) for every row, strictly somewhere — a sufficient condition for convergence of Jacobi/Gauss-Seidel iterations.

📘 Worked Example

Solve x + y = 3, 2x − y = 0 by Gauss-Seidel from (0, 0): From eq1: x = 3 − y → x₁ = 3 From eq2: y = 2x → y₁ = 2(3) = 6 Check: 2(3) − 6 = 0 ✓ Iterate: x₂ = 3 − 6 = −3, y₂ = 2(−3) = −6; x₃ = 9, y₃ = 18 — DIVERGES! Rows are NOT diagonally dominant (row2: |−1| < 2). Swap equation order: now x from eq(2x−y=0): x = y/2 → x₁ = 0; y = 3 − x → y₁ = 3; x₂ = 1.5, y₂ = 1.5; x₃ = 0.75...→ converging to (1, 2) ✓ Lesson: equation ORDER decides convergence — reorder for dominance.

Teacher's note: This example shows why understanding the convergence conditions is crucial — blindly applying a method without checking if it will converge wastes time and gives wrong answers!

  1. Would you expect Jacobi or Gauss-Seidel to converge? Why?
  2. Which method would be faster for solving this system if you had 100 different right-hand sides?

3. Lagrange & Newton's Difference Formulas

⏱ 60 min🔗 Prereq: None

🎯 Learning Objectives

By the end of this module, you should be able to:

  • Construct interpolating polynomials using Lagrange and Newton's methods
  • Choose the appropriate interpolation method based on data spacing and location of interest
  • Understand the trade-offs between global polynomials (Lagrange/Newton) and piecewise methods (splines)
  • Apply interpolation to engineering problems like estimating properties from tabulated data
  • Recognize when high-degree polynomial interpolation can lead to oscillations (Runge's phenomenon)

📝 Theory Notes

Big idea: interpolation draws the unique polynomial through your data points and reads between them. Equal spacing? Newton's forward/backward saves work. Uneven spacing? Lagrange or divided differences.
  • Lagrange (unequal spacing friendly):
$P(x)=\\sum_{k} y_k\\prod_{j\\ne k}\\dfrac{x-x_j}{x_k-x_j}$ — no table needed, weights built straight from nodes.
  • Divided differences: build a triangle: first column f[x_i,x_j] = (f_j−f_i)/(x_j−x_i); higher columns repeat on shorter intervals. Top entries become coefficients of Newton's divided-difference polynomial.
  • Equal spacing shortcuts: define Δ (forward) and ∇ (backward) differences; then:
Newton forward (near top): $P(x_0+hu)=y_0+u\\Delta y_0+\\dfrac{u(u-1)}{2!}\\Delta^2y_0+\\dfrac{u(u-1)(u-2)}{3!}\\Delta^3y_0+\\cdots$ Newton backward (near bottom): replace u→v measured from last node with ∇ differences.
  • Choosing: interpolate close to the START → forward; close to END → backward; middle → central/Stirling (beyond scope) or fit divided difference.

⚠️ Common Mistakes to Avoid

  • Using high-degree polynomials with many points: This can cause wild oscillations between points (Runge's phenomenon). Consider splines for many data points.
  • Extrapolating beyond your data: Interpolation is only reliable between your data points. Going outside can give nonsense results.
  • Ignoring data spacing: Newton's forward/backward methods assume equal spacing — using them with uneven spacing introduces errors.
  • Not checking if data represents a function: Interpolation assumes each x maps to exactly one y. If your data fails the vertical line test, you need a different approach.
  • Computational inefficiency: Lagrange formula requires O(n²) work for each evaluation. Newton's form with divided differences is more efficient for multiple evaluations.

💡 Tips & Tricks

  • Choose your method based on your goal:
    • Need to evaluate at many points? Newton's divided difference form is most efficient.
    • Have unevenly spaced data? Lagrange or divided differences (avoid forward/backward unless spacing is equal).
    • Interpolating near the beginning of your data? Use Newton forward.
    • Interpolating near the end? Use Newton backward.
  • Engineering application: Thermodynamic tables (steam tables), material properties vs temperature, wind tunnel test data — all use interpolation to get values at conditions not explicitly tabulated.
  • Quality check: For smooth functions, the interpolating polynomial should behave reasonably between points. If it oscillates wildly, you might be overfitting.
  • Piecewise is often better: For many data points, consider cubic splines instead of a single high-degree polynomial.

📖 Exam Definitions — quote these in your answers

  • Interpolation: Estimating the value of a function between known tabulated points using a polynomial fitted through those points.
  • Shift operator Δ: Δy(x) = y(x+h); repeated application builds the forward-difference table used in Newton's formulas.
  • Divided difference: The coefficient f[x₀,…,xₖ] defined recursively as (f[x₁,…,xₖ] − f[x₀,…,xₖ₋₁])/(xₖ − x₀), symmetric in its arguments.
  • Lagrange interpolation: Direct construction of the interpolating polynomial as a weighted sum of node-specific basis polynomials, valid for unequal spacing.

📘 Worked Example

Points (1, 1), (2, 8), (3, 27) — estimate f(2.5) by Lagrange: $P=\\dfrac{(2.5-2)(2.5-3)}{(1-2)(1-3)}(1)+\\dfrac{(2.5-1)(2.5-3)}{(2-1)(2-3)}(8)+\\dfrac{(2.5-1)(2.5-2)}{(3-1)(3-2)}(27)$ = 0.125(1) + 0.75(8) + 0.125·? recompute third weight: (1.5×0.5)/2 = 0.375 → 0.375×27 = 10.125 Total = 0.125 + 6 + 10.125 = $\\mathbf{16.25}$ — exact, since data came from x³ and P is cubic-degree ≤ 2? (16.25 vs true 15.625 shows quadratic fit limitation — good discussion point.)

Teacher's note: The fact that we get 16.25 instead of the true 15.625 reveals something important: with only 3 points, we can only fit a quadratic polynomial perfectly. Since the true function is x³ (cubic), there's an inherent limitation. This is why more points generally give better approximations — up to a point!

  • Recognize when high-degree polynomial interpolation can lead to oscillations (Runge's phenomenon)

📝 Theory Notes

Big idea: interpolation draws the unique polynomial through your data points and reads between them. Equal spacing? Newton's forward/backward saves work. Uneven spacing? Lagrange or divided differences.
  • Lagrange (unequal spacing friendly):
$P(x)=\\sum_{k} y_k\\prod_{j\\ne k}\\dfrac{x-x_j}{x_k-x_j}$ — no table needed, weights built straight from nodes.
  • Divided differences: build a triangle: first column f[x_i,x_j] = (f_j−f_i)/(x_j−x_i); higher columns repeat on shorter intervals. Top entries become coefficients of Newton's divided-difference polynomial.
  • Equal spacing shortcuts: define Δ (forward) and ∇ (backward) differences; then:
Newton forward (near top): $P(x_0+hu)=y_0+u\\Delta y_0+\\dfrac{u(u-1)}{2!}\\Delta^2y_0+\\dfrac{u(u-1)(u-2)}{3!}\\Delta^3y_0+\\cdots$ Newton backward (near bottom): replace u→v measured from last node with ∇ differences.
  • Choosing: interpolate close to the START → forward; close to END → backward; middle → central/Stirling (beyond scope) or fit divided difference.

⚠️ Common Mistakes to Avoid

  • Using high-degree polynomials with many points: This can cause wild oscillations between points (Runge's phenomenon). Consider splines for many data points.
  • Extrapolating beyond your data: Interpolation is only reliable between your data points. Going outside can give nonsense results.
  • Ignoring data spacing: Newton's forward/backward methods assume equal spacing — using them with uneven spacing introduces errors.
  • Not checking if data represents a function: Interpolation assumes each x maps to exactly one y. If your data fails the vertical line test, you need a different approach.
  • Computational inefficiency: Lagrange formula requires O(n²) work for each evaluation. Newton's form with divided differences is more efficient for multiple evaluations.

💡 Tips & Tricks

  • Choose your method based on your goal:
    • Need to evaluate at many points? Newton's divided difference form is most efficient.
    • Have unevenly spaced data? Lagrange or divided differences (avoid forward/backward unless spacing is equal).
    • Interpolating near the beginning of your data? Use Newton forward.
    • Interpolating near the end? Use Newton backward.
  • Engineering application: Thermodynamic tables (steam tables), material properties vs temperature, wind tunnel test data — all use interpolation to get values at conditions not explicitly tabulated.
  • Quality check: For smooth functions, the interpolating polynomial should behave reasonably between points. If it oscillates wildly, you might be overfitting.
  • Piecewise is often better: For many data points, consider cubic splines instead of a single high-degree polynomial.

📖 Exam Definitions — quote these in your answers

  • Interpolation: Estimating the value of a function between known tabulated points using a polynomial fitted through those points.
  • Shift operator Δ: Δy(x) = y(x+h); repeated application builds the forward-difference table used in Newton's formulas.
  • Divided difference: The coefficient f[x₀,…,xₖ] defined recursively as (f[x₁,…,xₖ] − f[x₀,…,xₖ₋₁])/(xₖ − x₀), symmetric in its arguments.
  • Lagrange interpolation: Direct construction of the interpolating polynomial as a weighted sum of node-specific basis polynomials, valid for unequal spacing.
